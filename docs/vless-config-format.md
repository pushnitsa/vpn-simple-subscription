# VLESS Configuration & URI Format Specification

This document details the standard URI format and query parameters for `vless://` connection links used across Xray-core clients (e.g., v2rayN, v2rayNG, NekoBox, Sing-box, Shadowrocket, and Hiddify).

---

## 1. General URI Scheme

A standard VLESS configuration link follows this URI format:

```text
vless://<UUID>@<server>:<port>?<query-parameters>#<remark>
```

### Components

| Component | Required | Description | Example |
| :--- | :---: | :--- | :--- |
| `vless://` | **Yes** | Protocol scheme identifier. | `vless://` |
| `<UUID>` | **Yes** | User ID formatted as a standard UUID (v4). | `00000000-0000-0000-0000-000000000000` |
| `<server>` | **Yes** | Remote server address (Domain name, IPv4, or `[IPv6]`). | `example.com` or `192.0.2.1` |
| `<port>` | **Yes** | Destination port on the proxy server. | `443` |
| `?<query-parameters>`| **Yes** | URL-encoded parameters configuring transport, security, and flow. | `?type=xhttp&security=tls...` |
| `#<remark>` | No | URL-encoded profile alias/display name in client applications. | `#My-Proxy` |

---

## 2. Core & Security Parameters

| Parameter | Required | Values / Format | Description |
| :--- | :---: | :--- | :--- |
| `encryption` | **Yes** | `none` | VLESS payload encryption. Defaults to `none` (encryption handled by outer TLS/REALITY wrapper). |
| `security` | **Yes** | `none` \| `tls` \| `reality` | Security mechanism wrapping the connection stream. |
| `flow` | No | `xtls-rprx-vision` | Flow control sub-protocol (used primarily with `type=tcp` + TLS/REALITY). |

---

## 3. TLS & REALITY Parameters

When `security=tls` or `security=reality`, the following parameters apply:

| Parameter | Used With | Description | Example |
| :--- | :--- | :--- | :--- |
| `sni` | TLS / REALITY | Server Name Indication sent during handshake. | `sni=example.com` |
| `fp` | TLS / REALITY | Client uTLS fingerprint impersonation. | `fp=chrome`, `fp=firefox`, `fp=randomized` |
| `alpn` | TLS | Application-Layer Protocol Negotiation (comma-delimited). | `alpn=h2,http/1.1` |
| `pbk` | REALITY | X25519 Public Key generated by the server. | `pbk=SbVKOEMjK0s...` |
| `sid` | REALITY | Short ID (hexadecimal) configured on server inbound. | `sid=01234567` |
| `spx` | REALITY | SpiderX path crawler parameter. | `spx=%2F` |
| `allowInsecure` | TLS | Allow untrusted/self-signed certificates (`1` or `true`). | `allowInsecure=1` |

## 4. Transport Types (`type`)

### 4.1. TCP (`type=tcp`)
* `headerType`: Obfuscation header type (`none`, `http`).

### 4.2. WebSocket (`type=ws`)
* `path`: WebSocket endpoint URL path (must be URL-encoded, e.g. `%2Fws`).
* `host`: HTTP `Host` header sent during handshake.

### 4.3. gRPC (`type=grpc`)
* `serviceName`: gRPC service identifier name.
* `mode`: Mode of connection (`gun` or `multi`).

### 4.4. XHTTP (`type=xhttp`)
Modern HTTP-based transport introduced in Xray-core for robust multiplexing and anti-censorship:
* `path`: HTTP request URL path (URL-encoded, e.g. `%2Fpath`).
* `host`: HTTP `Host` header.
* `mode`: Operational stream mode:
  * `packet-up`: Optimized packet-based upstream.
  * `stream-up`: Stream-based upstream.
  * `stream-one`: Single bi-directional stream.
* `extra`: **URL-encoded JSON string** containing advanced transport settings (see section 5).
* `x_padding_bytes`: Optional query string alias for padding range (e.g., `100-1000`).

---

## 5. XHTTP `extra` Parameter Structure

The `extra` query parameter accepts a URL-encoded JSON object with advanced configuration fields:

### Unencoded JSON Schema
```json
{
  "mode": "packet-up",
  "xPaddingBytes": "100-1000",
  "noGRPCHeader": false,
  "headers": {
    "Referer": "https://example.com/"
  },
  "xmux": {
    "maxConcurrency": "128-256",
    "cMaxReuseTimes": "32-64",
    "hMaxRequestTimes": "300000-600000",
    "hKeepAlivePeriod": 30
  }
}
```

### Encoded Query Value
```text
extra=%7B%22mode%22%3A%22packet-up%22%2C%22xPaddingBytes%22%3A%22100-1000%22%7D
```

## 6. Examples

### VLESS + TCP + REALITY + Vision (Standard)
```text
vless://00000000-0000-0000-0000-000000000000@example.com:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=example.com&fp=chrome&pbk=SbVKOEMjK0sIlbwg4akyBg5mL5KZwwB-ed4eEE7YnRc&sid=01234567&type=tcp#Node-Reality
```

### VLESS + WebSocket + TLS
```text
vless://00000000-0000-0000-0000-000000000000@example.com:443?encryption=none&security=tls&sni=example.com&fp=chrome&alpn=h2,http/1.1&type=ws&path=%2Fvless-ws&host=example.com#Node-WS
```

### VLESS + XHTTP
```text
vless://00000000-0000-0000-0000-000000000000@example.com:443?encryption=none&security=none&type=xhttp&host=example.com&mode=packet-up&path=%2F8AUe2iyGSFVzxTx72zEe&extra=%7B%22mode%22%3A%22packet-up%22%2C%22xPaddingBytes%22%3A%22100-1000%22%7D&x_padding_bytes=100-1000#Node-XHTTP
```

## 7. Subscription Delivery Considerations

For subscription providers like `vpn-simple-subscription`:
1. **Multi-Node Lists**: Multiple connection strings are joined with newline characters (`\n`).
2. **Encoding**: The newline-separated string is Base64-encoded when served to standard V2Ray/Xray subscription clients.
3. **Display Titles**: Client remark names can either be appended as the `#<remark>` fragment at the end of the URI, or managed via subscription metadata depending on client capabilities.
